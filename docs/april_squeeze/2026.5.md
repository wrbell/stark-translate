## What Failed (Do Not Repeat)

| Experiment | Result | Root Cause |
|-----------|--------|------------|
| W15 curriculum (hard-only, lr=5e-5, init W14) | 64.76% WER (was 7.61%) | train_loss 0.9487 → init-from likely didn't load weights; hard-only data destroys general ability |
| W15b curriculum (hard-only, lr=1e-5, init W14) | 64.76% WER | Same failure mode, lower LR didn't help |
| S8 pure DeepL (5K pairs) | COMET -0.010 vs base | Negative transfer — DeepL-only without verse mixing hurts |
| S9 pure DeepL (10K pairs) | COMET -0.023 vs base | Worse at scale — more bad data = more regression |
| TurboQuant on CUDA (512-token context) | KV cache = 50-100MB | Saving 75% of 50MB is noise on 12-16GB cards |

## What's Uncertain (Awaiting Data)

- Gemma 4 E2B/E4B translation quality (benchmark running, results pending)
- Gemma 4 E2B tokenizer compatibility with TranslateGemma (cross-family spec decode)
- llama.cpp vs HF speedup on RTX 3060 (no benchmark data yet)
- EAGLE-3 acceptance rate on translation tasks (no public head for Gemma 3)
- Whether `--init-from` in `train_whisper.py` correctly loads adapter weights
- W16 mixed-data approach (untested hypothesis)

## Cross-Pillar: Speculative Decode Rejection Logging

Speculative decoding generates free training signal — every rejected draft token reveals exactly where the 4B model diverges from 12B (or where the EAGLE head mispredicts). This data feeds directly into Pillar 3 fine-tuning and replaces the failed W15 hard-mining approach with organic, inference-time difficulty discovery.

### What to Log

| Field | Type | Training Use |
|-------|------|--------------|
| `source_text` | str | Input that caused rejection |
| `draft_tokens` | list[int] | What 4B/EAGLE proposed |
| `accepted_tokens` | list[int] | What 12B verified |
| `rejection_positions` | list[int] | Token indices where draft was wrong |
| `rejected_words` | list[str] | Decoded rejected tokens (human-readable) |
| `acceptance_rate` | float | Per-sequence acceptance ratio |
| `domain` | str | "verse" / "sermon" / "live" — from pipeline context |
| `theological_terms` | list[str] | Tier 1 terms present in source (cross-ref with glossary) |
| `timestamp` | str | ISO 8601 |

### Output Format

JSONL at `metrics/spec_decode_rejections_{date}.jsonl`, following the same pattern as `engines/active_learning.py` fallback event logging.

```jsonl
{"source_text": "Christ's atonement...", "acceptance_rate": 0.72, "rejected_words": ["expiación", "propiciación"], "domain": "sermon", "theological_terms": ["atonement"], "timestamp": "2026-04-28T14:30:00Z"}
```

### Implementation

**Phase 1D integration (both HF and EAGLE paths):**

| Engine | Where to hook | How |
|--------|--------------|-----|
| `CUDAGemmaStreamingEngine` | `translate()` when `assistant_model` is set | HF `generate()` returns `assistant_model_output` with acceptance mask when `output_attentions=True` — extract rejection positions |
| `SGLangEagleEngine` (EAGLE) | EAGLE inference loop | SpecForge/SGLang exposes per-step accept/reject — log each rejection with draft vs verified token |
| `MLXGemmaEngine` | `translate()` when `draft_model` is set | `mlx_lm.generate(draft_model=)` — hook into verification step |

**Integration with active learning loop:**

The rejection JSONL becomes input to the next fine-tuning cycle:
1. **For TranslateGemma:** Low-acceptance-rate sentences → priority data for S-round training (replaces DeepL synthetic with real failure cases)
